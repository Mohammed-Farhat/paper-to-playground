# Design brief: page template

This file is for the teammate who owns the page design. The agent fills one generic template for every paper, so a design change improves every generated page.

## Files you own

| File | What it is |
|---|---|
| `templates/page.html` | Page layout and all CSS, in the `<style>` block. **This is the main design file.** |
| `templates/lib.js` (optional) | SVG chart helpers. Only the colors and font sizes are design choices: `PALETTE`, `L.heat`, `L.diverge`, and the `size:` values in `L.bars` / `L.heatmap` / `L.plot`. |

Do not edit `templates/runtime.js` or anything in `p2p/` without telling the backend owner. The checks depend on them.

## Hard rules (from the hackathon spec)

- **Self-contained:** no CDN, no web fonts, no remote images, no `@import`, no build step. Use system font stacks only (`system-ui, "Segoe UI", Roboto, ...`).
- **Must work in Chromium**, opened locally (`index.html` served from a folder).
- **Explanation over decoration:** readable labels, good contrast, and a clear reading order (idea, symbols, playground, explorations, caveat, sources).
- **Phone-width layout must not scroll horizontally.** Wide matrices may scroll inside their own box.

## Contract: keep these or the agent breaks

### Placeholders (replaced by `p2p/build.py`)

`{{TITLE}}` `{{HOOK}}` `{{META}}` `{{IDEA}}` `{{WHY}}` `{{EQUATIONS}}` `{{SYMBOLS}}` `{{VISUAL_CAPTION}}` `{{EXPLORATIONS}}` `{{PITFALL_HEADING}}` `{{PITFALL_TEXT}}` `{{GROUNDING}}` `{{FOOTER}}` `{{SPEC_JSON}}` `{{LIB_JS}}` `{{MODEL_JS}}` `{{RUNTIME_JS}}`

- Each placeholder must appear exactly once. You may move them around.
- Keep the four `<script>` blocks at the end of `<body>`, in this order: spec JSON, lib, model, runtime.

### Element IDs (used by the runtime and the checker)

`idea`, `symbols`, `p2p-playground`, `p2p-controls`, `p2p-reset`, `p2p-visual`, `p2p-error`, `p2p-values`, `p2p-checks` (must be a `<ul>`), `explore`, `caveat`, `grounding`

## Suggested design priorities

1. **Make the visual large.** On desktop the SVG should get about 700px or more of width. The current two-column layout shrinks it; consider controls beside it only when the screen is wide, or controls above it.
2. **Visual hierarchy for the learning sequence**, with clear numbered sections.
3. **Clear "from the paper" vs "our simplification" styling** in the grounding section. The assessors check this distinction.
4. **Accessible contrast and focus states** for the controls.

## How to preview your changes without calling the API

Re-render any saved run with the current template (no API key or tokens needed):

```bash
python tools/rerender.py docs/fixtures/attention
```

Then open `docs/fixtures/attention/index.html` in Chrome. Fixtures for both public examples are in `docs/fixtures/` (generated by the agent with `P2P_SAVE_SPEC=1`).
